## 一、系统概述

RIMS 面向科研院所的科研项目管理场景，覆盖「**项目申报 → 部门审核 → 科研处立项 → 进度与经费管理 → 成果登记 → 结题验收**」的完整闭环。系统提供分层的角色权限体系、全流程审批留痕、经费分科目额度管控、里程碑与预算执行预警，以及面向管理者的看板与操作审计。

系统特性：

- **主链路贯通**：从草稿申报到结题归档，项目状态在受控状态机中流转，每一步迁移留痕、可回溯。
- **权限双层控制**：接口层按角色门禁，数据层按「本人 / 本部门 / 全院」过滤可见范围，避免越权访问。
- **经费硬管控**：按科目管理预算额度，支出申请与审批分别校验，并以原子方式占用额度，杜绝并发下的预算击穿。
- **开箱即用**：默认使用 H2 文件型数据库持久化，重启不丢数据；一条命令启动，接口与页面同端口。
- **可验证**：提供后端集成测试与端到端冒烟测试，交付方可自行复跑验证。

## 二、功能范围

### 2.1 角色与权限

系统内置 5 类角色，权限在接口层与数据层同时生效。

| 角色 | 代码 | 核心职责 |
| --- | --- | --- |
| 科研人员 | `RESEARCHER` | 项目申报、执行填报、经费申请、成果登记、结题申请 |
| 部门管理员 | `DEPT_ADMIN` | 本部门项目初审（第一级审批） |
| 科研处管理员 | `ADMIN` | 立项审批、结题验收、预算调整、项目终止、全院数据、审计日志 |
| 财务 | `FINANCE` | 经费支出审批 |
| 院领导 | `LEADER` | 全院只读看板与预警 |

数据可见范围：

- 科研人员 —— 本人负责或参与的项目；
- 部门管理员 —— 本部门项目 + 本人参与的项目；
- 科研处 / 财务 / 院领导 —— 全院项目。

此外，关键动作在服务层二次校验：非项目负责人不得提交申报，部门管理员不得执行科研处立项环节，跨部门审核直接拒绝。

### 2.2 项目全生命周期

| 功能 | 说明 | 关键约束 |
| --- | --- | --- |
| 申报草稿 | 基本信息、研究内容、团队成员、预算科目编制 | 预算科目合计须等于预算总额 |
| 两级审批 | 部门审核 → 科研处立项 | 驳回必须填写意见 |
| 状态机 | 草稿 / 待部门审核 / 待科研处立项 / 执行中 / 待验收 / 已结题 / 已驳回 / 已终止 | 状态仅在单一服务中修改 |
| 审批留痕 | 记录操作人、时间、来源状态、目标状态、审批意见 | 与审计日志职责分离 |
| 里程碑 | 计划完成日期、实际完成日期 | 逾期不落库，由计划日期实时判定并进入预警 |
| 进度填报 | 完成百分比、本期工作、存在问题、下期计划 | 保留历史记录，形成项目时间线 |
| 成果登记 | 论文 / 专利 / 软著 / 标准 / 研究报告 | 结题申请前须至少登记 1 项成果 |

### 2.3 经费管理

| 功能 | 说明 |
| --- | --- |
| 科目预算 | 设备费、材料费、差旅费、劳务费、其他共 5 个科目 |
| 支出申请 | 项目组成员在执行期内按科目发起申请 |
| 支出审批 | 财务或科研处管理员审批，通过即计入支出，驳回则释放占用额度 |
| 额度控制 | 分科目控制；申请时占用额度、审批驳回时释放；额度调整不得低于已占用金额 |

### 2.4 管理看板与审计

- **工作台**：项目总数、在研数、待办数、预算执行率、项目状态分布、经费执行趋势、近 6 个月支出、风险预警。
- **审批中心**：按当前角色聚合待审核项目、待立项项目、待验收项目、待审批经费。
- **审计日志**：记录关键操作（创建、修改、提交、审批、登录等）的主体、对象、来源与时间，仅科研处管理员可查询。

## 三、技术架构

| 层级 | 职责 | 关键实现 |
| --- | --- | --- |
| 接入层 | HTTP 接入、鉴权、跨域 | Spring Boot 内嵌 Tomcat，单端口同时提供 API 与前端页面 |
| 接口层 | 参数校验、响应封装 | `Result{code,message,data}` 统一响应 + `@RestControllerAdvice` 全局异常处理 |
| 业务层 | 业务规则、状态流转、事务边界 | `WorkflowService` 为状态机唯一入口；`ProjectService` 负责数据维护、不修改状态 |
| 数据访问层 | 条件拼接、分页、原子更新 | MyBatis-Plus `LambdaQueryWrapper`、分页插件、乐观锁插件、自定义原子 UPDATE |
| 持久层 | 结构与索引 | 11 张业务表，金额统一 `DECIMAL(14,2)`，逻辑删除 |
| 前端层 | 视图与状态 | Vue 3 组合式 API，路由 + Pinia，按角色控制页面元素可见性 |

架构要点：

- **状态机单一入口**：`Project.status` 仅由 `WorkflowService` 修改，"谁可以从哪个状态走到哪个状态"只有一份真相。
- **审批与审计分离**：`approval_record` 只记录状态迁移，`audit_log` 记录全部关键动作，职责不混淆。
- **避免 N+1 查询**：列表页的「已支出」「最新进度」以一次 `IN` 查询后在内存分组。
- **跨域白名单**：允许来源由 `rims.cors.allowed-origins` 配置，默认仅放行本机 8080 / 5173，不使用通配符。

## 四、部署与运行

### 4.1 环境要求

| 依赖 | 版本 | 是否必需 |
| --- | --- | --- |
| JDK | 17 及以上 | 必需（运行 jar） |
| Maven | 3.8 及以上 | 仅源码构建时需要 |
| Node.js | 18 及以上 | 仅开发或重新构建前端时需要 |

### 4.2 直接运行（推荐）

在项目根目录执行：

```bash
java -jar dist/rims-backend.jar
```

启动后访问 <http://localhost:8080>，接口与页面同端口。首次启动会在**运行目录**下创建 `data/` 目录，写入 H2 文件库并初始化演示数据。

### 4.3 开发模式（前后端分离、热更新）

```bash
# 终端 1：后端
cd backend
mvn spring-boot:run

# 终端 2：前端
cd frontend
npm install
npm run dev
```

前端开发服务器运行在 <http://localhost:5173>，`/api` 已代理至 8080 端口。

### 4.4 从源码构建

```bash
# 1. 构建前端（产物输出至 backend/src/main/resources/static）
cd frontend && npm install && npm run build

# 2. 打包后端（内含前端产物）
cd ../backend && mvn clean package

# 3. 产出可执行 jar
cp target/rims-backend.jar ../dist/rims-backend.jar
```

> 后端构建已显式声明源码编码为 UTF-8（`project.build.sourceEncoding`），确保中文提示在任意操作系统下均正确编译。

### 4.5 切换 MySQL 8

```sql
CREATE DATABASE rims DEFAULT CHARACTER SET utf8mb4;
```

```bash
java -jar dist/rims-backend.jar --spring.profiles.active=mysql \
  --MYSQL_HOST=127.0.0.1 --MYSQL_USER=root --MYSQL_PASSWORD=你的密码
```

建表脚本 `backend/src/main/resources/db/schema.sql` 同时兼容 H2（MySQL 模式）与 MySQL 8。

### 4.6 数据重置

数据默认持久化于运行目录下的 `data/rims.mv.db`。恢复初始演示数据：停止服务 → 删除 `data/` 目录 → 重新启动。

### 4.7 由旧版本数据库升级

若数据库来自早期版本（缺少 `project.version`、`expense.version`、`budget_item.reserved_amount` 三列），**无需手工执行 DDL**：应用启动时会自动检测并补齐缺失列，并按「已通过 + 审批中」重新回填各科目的占用额度，保证升级前后的额度口径一致。升级过程不修改既有业务数据。

## 六、质量保障与验证

### 6.1 后端集成测试

`backend/src/test` 下包含 3 个测试类、7 个用例，通过 `@SpringBootTest` + `MockMvc` 启动完整 Spring 上下文（拦截器、服务层、Mapper、内存 H2），以真实 HTTP 请求验证业务规则：

| 测试类 | 覆盖内容 |
| --- | --- |
| `AuthAndAccessTest` | 未登录访问被拦截、错误密码被拒、正确登录签发令牌 |
| `WorkflowStateMachineTest` | 研究人员越权审批被拒（403）、非法状态流转被拒、正常推进至执行中 |
| `FinanceBudgetTest` | 预算占用、额度超限被拒、审批通过占用不变、驳回后额度回退 |

执行：

```bash
cd backend && mvn test
```

### 6.2 端到端冒烟测试

`scripts/smoke-test.mjs` 使用 Node 内置 `fetch` 真实走完「申报 → 部门审核 → 立项 → 里程碑 / 进度 / 成果 / 经费 → 结题验收 → 审批留痕与审计」全链路，共 26 项断言，其中 5 项专门验证越权与非法操作被拦截。

```bash
# 需先启动后端服务
node scripts/smoke-test.mjs
```

期望输出：`== 结果：26 通过 / 0 失败 ==`。

### 6.3 并发与数据一致性

系统在两处关键写入路径上采用了数据库层面的并发控制，而非应用层的「先查后写」：

| 场景 | 风险 | 实现方式 |
| --- | --- | --- |
| 项目状态流转 | 并发审批导致状态被覆盖、产生重复审批记录 | `project` 表带 `version` 字段（乐观锁），更新后校验受影响行数，命中 0 行即返回 409 冲突提示 |
| 经费单据审批 | 并发审批导致同一单据被重复处理 | `expense` 表带 `version` 字段（乐观锁），审批前校验受影响行数 |
| 预算额度占用 | 并发申请导致同一科目超支 | `budget_item` 维护 `reserved_amount`，占用 / 释放均为带条件的原子 `UPDATE`，由数据库行锁保证互斥 |

### 6.4 安全基线

| 项目 | 措施 |
| --- | --- |
| 口令存储 | BCrypt 加盐哈希，不可逆 |
| 令牌 | JWT（HS256），密钥经 SHA-256 派生；生产环境通过 `RIMS_JWT_SECRET` 环境变量注入 |
| 令牌生命周期 | 默认 12 小时；请求上下文在请求结束时清理，避免线程复用导致身份串号 |
| 跨域 | 来源白名单可配置，默认仅放行本机地址，不启用通配符 + 携带凭证的组合 |
| SQL | 全部使用参数化查询（MyBatis-Plus / 注解参数），无字符串拼接 |
| 审计 | 关键操作落库，含操作人、对象、来源、时间 |

### 6.5 调试入口

| 入口 | 地址 | 说明 |
| --- | --- | --- |
| Swagger UI | <http://localhost:8080/swagger-ui.html> | 接口文档与在线调试 |
| H2 控制台 | <http://localhost:8080/h2-console> | JDBC URL `jdbc:h2:file:./data/rims`，用户 `sa`，口令为空 |
| 统一响应 | `{ "code": 0, "message": "ok", "data": ... }` | `code != 0` 表示业务失败，`message` 为可直接展示的中文提示 |
| 鉴权方式 | `Authorization: Bearer <token>` | 登录接口签发令牌 |

## 八、已知限制与演进方向

**当前限制**

1. 附件上传（任务书、发票、结题报告）未纳入范围，真实业务中需补充。
2. 消息通知（邮件 / 站内信）未实现，待办依赖用户主动查看工作台。
3. 单院所单租户，未做多租户隔离与数据密级区分。
4. 工作台指标采用内存聚合，数据量达到万级项目时需改为 SQL 聚合。
5. 审计日志未做归档与分级保留，长期运行会持续增长。
6. 前端 ECharts 为全量引入，首屏包体积偏大，生产环境建议按需引入。

**后续演进优先级**

1. 附件上传与结题材料打包。
2. 与财务系统对接（凭证导出、对账）。
3. 消息通知（站内信 + 邮件），将待办主动推送到人。
4. 申报书与结题报告模板导出（Word / PDF）。
5. 数据权限细化到项目密级，支持涉密项目隔离。
